# 2026-05-04 — Rename `cboone-cc-plugins` to `agent-harness-plugins`

## Context

The repository was renamed at GitHub (`cboone/cboone-cc-plugins` → `cboone/agent-harness-plugins`) and on disk (`~/Development/cboone-cc-plugins` → `~/Development/agent-harness-plugins`). No other files were updated, so the codebase still advertises and refers to itself by the old name in 156 files (~563 occurrences) and across local agent harness state. We need to migrate every reference to the new name and ship a release that signals the change to downstream installers.

GitHub redirects the old slug, so currently nothing is broken, but the marketplace identifier `cboone-cc-plugins` is the catalog of record and downstream installers index plugins as `<plugin>@cboone-cc-plugins`. Once the marketplace `name` flips, every consumer's allowlist key changes, so this needs to land coherently in one pass and ship as a release.

Outcome: every committed reference says `agent-harness-plugins`; user-level Claude/Codex state continues to work after the marketplace name change; a clean release tag is cut.

## Decisions (settled with user)

- **Plugin versions**: bump patch on every plugin (`X.Y.Z` → `X.Y.(Z+1)`). The marketplace `metadata.version` (catalog state tag) is recomputed by `bin/compute-catalog-state`.
- **`docs/plans/done/`**: leave as-is — historical archive, per CLAUDE.md and user direction.
- **Shipping**: migrate and release directly on `main`, no PR. Frequent small GPG-signed commits at logical boundaries, then `/release` (or the `release` skill) to tag and publish.
