# Shared turn-failure notifications

A terminal API error or safeguard refusal posts a banner in every notify tier. An approval wait remains a separate event. This plan covers both harnesses through a linked pair of PRs, per the Inbox decision relayed by TOOLING at 8:41 PM ET on 2026-10-28.

## Shared contract

Each harness adapter supplies `kind` (`error` or `refusal`), a non-empty display `message`, and a non-empty `session_id` (Claude session or Codex thread). Presentation resolves the session's display name and tmux `session: window`; outside tmux it uses the existing repository/task subtitle. Missing names fall back to the session or thread ID. A missing message becomes a fixed description of the failure kind. Neither arbitrary message wording nor an approval request determines the kind.

Notify titles are `Error: <session>` or `Refusal: <session>`, with the existing `Worker:` prefix in the worker tier. The body is the bounded message, the subtitle identifies the tmux location, and the sound uses the permission role (`Funk` by default). These events bypass completion tier policy, origin/focus suppression, and completion deduplication. Subagent payloads remain excluded. Approval waits retain their existing approval titles and permission handling.
