## Adoption contract and limits

Keep native pane-title ownership and existing window names. Retain the local Codex adapter's subagent guard and question/interrupt handling; request CONFIG to review adding the missing permission registration and mapping, using upstream's event selection as reference. Do not run the upstream installer over existing hooks.

| Mark                                 | Claude setter                                        | Codex setter                                                 | Clear or replace                                             |
| ------------------------------------ | ---------------------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| Working: blue `` U+F021; tab `🐝`   | UserPromptSubmit/PostToolUse                         | Same                                                         | Wait, Stop or cleanup                                        |
| Waiting: yellow `` U+F251; tab `⏳` | Permission/elicitation notification; AskUserQuestion | PermissionRequest addition; existing request_user_input hook | Workmux focus acknowledgment, tool result, prompt or cleanup |
| Done: green, no extra glyph          | Root Stop                                            | Root Stop                                                    | Workmux focus acknowledgment or next state                   |
| Clear: no mark                       | Cleanup coverage unverified                          | Existing Interrupt mapping                                   | Next state                                                   |

`workmux set-window-status --help` confirms waiting/done auto-clear on focus. This acknowledges attention; it does not prove prompt resolution. Upstream subagent hooks and broad PostToolUse resets must not replace the root-only adapter without testing. Native Codex “Action Required” exists in binary descriptions; blocked entry/clearing, denial/cancel, parallel waits and dedicated error indication remain gaps. Adoption must not be described as complete lifecycle parity.
