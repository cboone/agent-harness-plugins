## Recommendation and acceptance

Retain the 30-second sampler and its five-minute macmon refresh; reuse existing CPU/GPU °C, fan RPM, CPU W and system-power estimate. Proposed additions are GPU/ANE/RAM W and fan names, plus battery-flow W from signed mA × mV / 1,000,000 every 30 seconds. Keep battery flow, SoC subsystem estimates and SMC system estimate separate; none is measured wall consumption. Defer registry power telemetry until its units and averaging windows are established. No new plugin or watcher is needed.

One timed probe cost macmon 0.71 s wall/0.12 s CPU, ioreg 0.02/0.01 s, pmset 0.01/0.00 s and notifyutil 0.00/0.00 s (rounded). Macmon every 300 seconds implies about 0.04% of one CPU core from this sample. Private APIs can disappear or mislabel sensors; reads add wakeups. Never enable fan writes, a helper or a metrics server. Before adoption, compare idle/load and AC/battery readings, measure repeated costs, and verify unavailable/zero sentinel handling, freshness and schema compatibility. Keep missing readings distinct from real zero and retain the current 20-second command timeout.

Keep `load_alerts_wait.py`'s existing thermal-pressure alerts (level ≥1 for 300 s; ≥2 for 60 s). Attach temperatures, RPM and watts with sample age as context; five-minute values cannot drive a 60-second decision. Calibrate any new sustained thresholds against this machine before enabling alerts; watts or RPM alone should not trigger them. Any faster cadence requires measured cost evidence and separate approval to change the live sampler.

No installation is proposed. Installed macmon 0.10.0 resolves to `/opt/homebrew/Cellar/macmon/0.10.0/bin/macmon`, SHA-256 `9d642452c5e2b4dde840809342504fa4d12187a377a6d6f2f9747a892154f926`. A future replacement needs a pinned artifact and checksum plus an exact command for you to run in a `salix` terminal. No plants apply to this documentation-only change.
