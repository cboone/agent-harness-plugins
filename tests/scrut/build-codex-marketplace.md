# Codex marketplace generation

Tests for the frontmatter translation in `bin/build-codex-marketplace`. Codex
has no `SKILL.md` frontmatter field for invocation policy and ignores
`disable-model-invocation`, so the generator drops that line from the Codex copy
and writes `agents/openai.yaml` instead. Every other field passes through,
because both Codex and OpenCode ignore what they do not recognize.

Every testcase starts from the fixture tree printed by
`tests/fixtures/codex-translation-fixture`: `alpha` sets
`disable-model-invocation: true`, `beta` sets no extended field, and `gamma`
sets `disable-model-invocation: false`.

## A skill that disables model invocation loses the line

```scrut
$ cd "$("${CODEX_TRANSLATION_FIXTURE_BIN}")" && "${BUILD_CODEX_MARKETPLACE_BIN}" > /dev/null && cat dist/codex/plugins/alpha/skills/alpha/SKILL.md
---
name: alpha
description: Fixture skill alpha. Use only in the build-codex-marketplace suite.
---

# alpha

This body exists so the skill parses. It carries no instructions.
```

## It gains an agents manifest stating the same policy

```scrut
$ cd "$("${CODEX_TRANSLATION_FIXTURE_BIN}")" && "${BUILD_CODEX_MARKETPLACE_BIN}" > /dev/null && cat dist/codex/plugins/alpha/skills/alpha/agents/openai.yaml
# Generated by bin/build-codex-marketplace from the canonical SKILL.md.
# Codex has no frontmatter field for invocation policy, so the Claude Code
# disable-model-invocation field is expressed here instead.
policy:
  allow_implicit_invocation: false
```

## A skill without extended fields is copied byte for byte

```scrut
$ cd "$("${CODEX_TRANSLATION_FIXTURE_BIN}")" && "${BUILD_CODEX_MARKETPLACE_BIN}" > /dev/null && cmp plugins/beta/skills/beta/SKILL.md dist/codex/plugins/beta/skills/beta/SKILL.md && echo identical
identical
```

## It gains no agents manifest

```scrut
$ cd "$("${CODEX_TRANSLATION_FIXTURE_BIN}")" && "${BUILD_CODEX_MARKETPLACE_BIN}" > /dev/null && ls dist/codex/plugins/beta/skills/beta
SKILL.md
```

`disable-model-invocation: false` is Codex's own default, so there is nothing to
express and the line stays where it is.

```scrut
$ cd "$("${CODEX_TRANSLATION_FIXTURE_BIN}")" && "${BUILD_CODEX_MARKETPLACE_BIN}" > /dev/null && cmp plugins/gamma/skills/gamma/SKILL.md dist/codex/plugins/gamma/skills/gamma/SKILL.md && ls dist/codex/plugins/gamma/skills/gamma
SKILL.md
```

## A second run produces the same tree

The generator removes and rewrites `dist/codex` on every run, so the translation
must be idempotent rather than applied twice.

```scrut
$ cd "$("${CODEX_TRANSLATION_FIXTURE_BIN}")" && "${BUILD_CODEX_MARKETPLACE_BIN}" > /dev/null && cp -R dist/codex first && "${BUILD_CODEX_MARKETPLACE_BIN}" > /dev/null && diff -r first dist/codex && echo unchanged
unchanged
```

## A skill that already ships an agents manifest fails the build

Merging an invocation policy into an existing `interface` or `dependencies`
block is a decision for whoever adds that file, so the generator refuses rather
than overwriting it.

```scrut
$ cd "$("${CODEX_TRANSLATION_FIXTURE_BIN}" own-manifest)" && "${BUILD_CODEX_MARKETPLACE_BIN}" 2>&1
::error::Skill 'plugins/alpha/skills/alpha' sets disable-model-invocation and ships its own agents/openai.yaml; merge the invocation policy into that file by hand
1 validation error(s); Codex marketplace build failed.
[1]
```
