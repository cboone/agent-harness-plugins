# .gitignore Template

Create `.gitignore` in the project root with the following content. If a `.gitignore` already exists, merge these entries into it rather than overwriting.

Replace `PROJECT-NAME` with the project name.

```gitignore
# System
.DS_Store

# Agent config
.claude/settings.local.json

# Secrets
.env
.env.*
!.env.example
!.env.sample
*.pem
*.key
*.p12
credentials.json
token.json

# Zig
.zig-cache/
zig-out/
release/
PROJECT-NAME
*.o
*.d
*.pdb
```

## Notes

- The System and Secrets sections are shared with all project types (from `scaffold-new-repo`).
- The Agent config section excludes local Claude Code settings that should not be committed. The tracked `.claude/settings.json` is committed on purpose, because the Zig build and format permissions in it apply to every contributor.
- `.zig-cache/` is the per-project build cache and `zig-out/` is the install prefix. Both are regenerated by `zig build` and neither belongs in history.
- `release/` holds the cross-compiled target directories the Makefile's `release` target writes.
- The bare `PROJECT-NAME` line covers the release workflow copying the binary to the repository root before archiving it. Without it, a failed release run leaves an untracked binary sitting in `git status`.
- `*.o`, `*.d` and `*.pdb` catch object, dependency and debug-symbol files from C interop and from Windows builds.
